# IFS 活動出席 — 操作手冊（繁體中文）

**程式名稱：** IFS 活動出席（IFS Event Attendance）  
**執行檔：** `ifs_attendance.exe`（單一檔案，無需安裝 Python）  
**適用：** 任何 IFS 活動（講座、培訓、說明會、研討會等）的入場／離場登記  

本手冊說明日常操作與**多站點（多部筆電）**流程，供現場操作員與活動管理員使用。

英文版摘要見 [USER_GUIDE.md](./USER_GUIDE.md)；多站點技術細節見 [MULTI_STATION.md](./MULTI_STATION.md)。

## 1. 程式做什麼

參加者出示 **中介人一戶通 QR Code**，掃描器（鍵盤楔入）會把網址貼進程式並按 Enter。程式會：

| 動作 | 說明 |
|------|------|
| **入場** | 記錄此人進入本活動／本機 |
| **離場** | 記錄此人離開（可在**另一部電腦**離場） |

資料存在程式旁邊的 **`agent.db`**。  
每部筆電各自一份資料庫；**整場活動的最終名單**在活動結束後，由管理員用「主控模式」合併各站點包後匯出。

---

## 2. 重要名詞

| 名詞 | 說明 |
|------|------|
| **身分** | QR 內的「保險中介人類別」+「保險中介人編號」（`categoryCode` + `licenseNo`） |
| **人次／造訪** | 一次入場起至離場（或尚未離場）的紀錄 |
| **在場（本機）** | 本機已入場、尚未在本機離場 |
| **簽到站（Desk）** | 一般模式：現場掃描登記 |
| **主控（Master）** | 管理員模式：匯入各站點包、合併、匯出全場 CSV（**不掃描**） |
| **站點** | 這部筆電的名稱與 ID（寫在 `station.toml`），合併時用來分辨資料來源 |
| **軟離場（跨站點離場）** | 本機沒有此人的入場紀錄時，仍可登記「離場意圖」；稍後主控會與其他站的入場配對 |
| **站點包** | 本機資料庫的匯出檔，給管理員匯入主控 |

## 3. 首次安裝與啟動

### 3.1 準備

1. 取得 `ifs_attendance.exe`（發行版單一檔）。  
2. 在每部筆電建立**獨立資料夾**，例如：  
   - `D:\IFS_Attendance\入口1\`  
   - `D:\IFS_Attendance\出口2\`  
3. 將 exe 複製進該資料夾（**不要**多部機共用同一個正在使用的資料夾／雲端同步資料夾）。

### 3.2 第一次開啟

1. 雙擊 `ifs_attendance.exe`。  
2. 程式會自動建立：  
   - `agent.db` — 出席資料庫  
   - `station.toml` — 站點設定（預設顯示名 `desk-1`）  
3. 建議立刻設定：  
   - **站點顯示名**（如 `入口-1`、`出口-2`）  
   - **活動名稱**（如 `2026 CPD 下午場`）  

見下方[第 5 節](#5-活動名稱與站點名稱設定)。

### 3.3 舊版 Python 資料庫

若資料夾內是舊 Python 版留下的 `agent.db`（內有 `attendance` 表）：

1. **先複製備份**（例如 `agent.db.pre-rust-日期.bak`）。  
2. 再用本程式開啟，會自動遷移為新結構。  
3. 遷移後請**只使用本程式**，勿再用舊 Python 程式開同一檔。

## 4. 畫面說明

### 4.1 上方列

| 項目 | 說明 |
|------|------|
| 標題 | 「IFS 活動出席」 |
| 活動名稱 | 已設定的活動名（未設定會顯示提示） |
| **時鐘** | 本機目前時間（持續更新） |
| **檔案** | 開啟／切換資料庫、匯出 CSV、匯出／匯入站點包、主控 CSV |
| **檢視** | 全螢幕、音效、活動／站點設定 |
| **說明** | 關於（路徑、站點 ID、音效狀態等） |

上方列下方另有一行狀態：**站點徽章**（站點名＋短 ID）、三個時段統計小籤（**✓ 成功**、**! 提醒**、**✕ 錯誤**，只計掃描，本次開啟程式起算）、**音效開／關**。

### 4.2 簽到站主要區塊

| 區塊 | 說明 |
|------|------|
| **入場 / 離場** 大按鈕 | 綠色＝入場、橙色＝離場；點選或按 **F1 / F2** 切換模式 |
| **模式橫幅** | 掃描框上方的整行色條：綠底「入場模式 Check-In」或橙底「離場模式 Check-Out」，兩米外也看得到目前模式 |
| **QR 輸入框** | 掃描器輸入處；掃描後送出 Enter 即處理。點過選單後會**自動搶回焦點**，掃描永不落空 |
| **目前在場** | 本機尚未離場人數 |
| **累計人次** | 本機入場過的不重複人數（同一人重複入場不會累加；含已離場者） |
| **本機成功** | 本次開啟程式後成功類掃描次數 |
| **最近結果** | 大結果卡：結果、身分、說明、時間、**多久以前**（也顯示匯出成功等系統訊息） |
| **本機近期掃描** | 最近約 12 筆**掃描**結果；可按 **「複製」** 複製「類別 · 編號」 |

### 4.3 主控模式額外區塊

| 區塊 | 說明 |
|------|------|
| **總出席（去重）** | 合併後不重複身分數 |
| **需覆核** | `needs_review` 筆數（建議人工看一眼） |
| **仍在場** | 合併後仍視為在場／僅入場等 |
| **主控儀表板** | 需覆核名單預覽、仍在場名單預覽 |

### 4.4 快捷鍵與音效

| 操作 | 方法 |
|------|------|
| 切到入場模式 | **F1**（或點綠色「入場」按鈕） |
| 切到離場模式 | **F2**（或點橙色「離場」按鈕） |
| 全螢幕 | **F11**，或 檢視 → 全螢幕 |
| 結束全螢幕 | 再按 F11 |
| 音效開／關 | 檢視 → 音效（預設**開**；設定存在資料庫） |
| 成功／失敗提示音 | 掃描後自動（可關閉） |

## 5. 活動名稱與站點名稱設定

路徑：**檢視 → 活動 / 站點設定…**（浮動視窗，不會推擠下方畫面；按右上角 ✕ 關閉）

| 欄位 | 存哪裡 | 作用 |
|------|--------|------|
| **活動名稱** | 資料庫 `app_meta` | 匯出 CSV 的 `event` 欄；檔名會帶活動簡稱 |
| **站點顯示名** | `station.toml` 的 `station_name` | 畫面上顯示；站點包檔名較好辨識 |
| **CPD 入場時間窗** | 資料庫 `app_meta` | 例：`14:30` 至 `15:00`；留白＝不限該邊界 |
| **CPD 離場時間窗** | 資料庫 `app_meta` | 例：`17:10` 至 `17:30` |
| **CPD 點數** | 資料庫 `app_meta` | 留白預設 2；匯出 CSV 的 `CPD` 欄顯示此點數 |

### 建議命名

| 站點角色 | 建議顯示名 |
|----------|------------|
| 正門入場 | `入口-1` |
| 側門入場 | `入口-2` |
| 正門離場 | `出口-1` |
| 側門離場 | `出口-2` |

### 注意

- **`station_id`（UUID）不要改**；只改顯示名。  
- 同一場活動各站應設**相同的活動名稱**，方便事後檔案管理。  
- 儲存後重開程式會載回同一資料夾內的設定。

## 6. 單機日常操作（簽到站）

### 6.1 開始前

1. 確認 Windows 時區正確。  
2. 開啟程式；確認站點名、活動名。  
3. 輸入框會自動保持焦點；若曾點過其他視窗，開掃前瞄一眼游標在框內即可。  
4. 用一張真實 QR 測掃：入場一次（**F1**）、離場一次（**F2**）。  
5. 需要大螢幕時按 **F11**。

### 6.2 入場登記

1. 點 **「入場」**（綠色）。  
2. 參加者出示一戶通 QR。  
3. 掃描器掃入 → 自動 Enter。  
4. 看 **最近結果**：應為 **「入場成功」**，並顯示類別與編號。  
5. **目前在場**、**累計人次**會更新。

### 6.3 離場登記（同一部機）

1. 點 **「離場」**（橙色）。  
2. 掃描同一人的 QR。  
3. 成功時顯示 **「離場成功」**。  
4. **目前在場**減 1。

### 6.4 重複入場

若本機此人仍在場又掃入場：

- 顯示 **「重複入場」**（琥珀色）  
- **不會**再寫一筆新的入場  
- 若對方其實已從別站離開，應在**離場模式**掃，或等主控合併後看全場狀態  

### 6.5 複製身分

在「本機近期掃描」列按 **「複製」**，可把「類別 · 編號」貼到備忘或通訊軟體（方便核對）。

### 6.6 混合櫃檯

同一部機又管入場又管離場：

- 入場潮 → 按 **F1** 切入場  
- 離場潮 → 按 **F2** 切離場  
- 切完瞄一眼掃描框上方的**模式橫幅**（整行綠＝入場、整行橙＝離場），顏色不對就先別掃

## 7. 掃描結果代表什麼

| 結果標題 | 意義 | 顏色感覺 |
|----------|------|----------|
| **入場成功** | 本機新增一筆入場 | 綠 |
| **重複入場** | 本機已在場，未重複寫入 | 黃／琥珀 |
| **離場成功** | 本機結束一筆在場造訪 | 綠 |
| **跨站點離場** | 本機沒有其入場，但已記錄離場意圖（正常，見多站點） | 藍 |
| **無法離場** | 軟離場關閉且本機無在場紀錄 | 琥珀 |
| **QR 無效** | 缺類別／編號或格式不對，未寫入 | 紅 |
| **操作失敗** | 系統／資料庫錯誤 | 紅 |
| **未輸入** | 空白送出 | 灰 |

結果卡還會顯示：

- 身分（類別 · 編號）  
- 補充說明（例如本機先前入場時間）  
- 回報時間  
- **多久以前**（如「3 秒前」「1 分 5 秒前」）

## 8. 單機匯出 CSV

**檔案 → 匯出出席 CSV…**

| 項目 | 說明 |
|------|------|
| 編碼 | UTF-8 含 BOM（Excel 可開中文） |
| 內容 | **本機**資料，不是全場 |
| 欄位概要 | event、ID、類別、編號、入場時間、離場時間、**CPD**、visit_uid |
| 預設檔名 | `IFS_attendance_07-August.csv`；有活動名時檔名會加簡稱 |

**CPD 欄規則：** 有設 CPD 時間窗時，入場**且**離場都在窗口內（以分鐘計、含端點）＝該活動的 CPD 點數；不符合＝`0`；未設時間窗＝留白。多站點的主控 CSV 也有同一欄（依每位中介人的首次入場／最後離場判定），記得在**主控資料庫**設同樣的時間窗（第 10 節）。

**這不是最終全場名單。** 多站點時請做[第 10 節主控合併](#10-活動結束主控合併)。

## 9. 多站點操作（重點）

### 9.1 為什麼需要特別流程？

現場常有：

- 從 **入口 A** 入場  
- 從 **出口 B 或 C** 離場  

每部筆電只寫**自己的** `agent.db`，且現場網路常不穩，所以：

- **活動進行中**：各站離線各自登記即可  
- **活動結束後**：用 USB 收集「站點包」，在管理員電腦合併成**主控結果**

```text
        [入口 A]  掃「入場」
              \
               → 會場
              /
        [出口 B]  掃「離場」（即使 A 才是入場站）
```

### 9.2 跨站離場如何成立？（軟離場）

| 情況 | 出口站行為 | 畫面 |
|------|------------|------|
| 此人在**本機**進過場 | 正常寫入離場時間 | **離場成功** |
| 此人在**別台**進場 | 仍記錄離場意圖 | **跨站點離場**（正常，不是錯誤） |

軟離場**預設開啟**。  
出口站**一定要掃離場**，不要因為「他不是在我這台進的」就不掃。

### 9.3 活動進行中：各站怎麼做

| 站點角色 | 模式 | 操作 |
|----------|------|------|
| 入場站 | **入場** | 每位進場者掃一次 |
| 離場站 | **離場** | 每位離場者掃一次（**含他站入場者**） |
| 混合站 | 依人潮切換 | 切模式時口頭／標示提醒同仁 |

**重要：**

1. **「目前在場」只代表本機**，不是全場即時人數。  
2. 全場真實名單以**結束後主控 CSV**為準。  
3. 禁止用 OneDrive／隨身碟「即時共用」正在寫入的 `agent.db`。  
4. 各站 `station_name` 要分得清楚（入口／出口）。

### 9.4 活動中不該做的事

| 錯誤做法 | 後果 |
|----------|------|
| 多機共用一個即時同步的 `agent.db` | 資料損壞、遺失 |
| 出口不掃「他站入場」的人 | 主控會顯示仍在場／需覆核 |
| 入場站誤用離場模式 | 出現大量跨站點離場或無法離場 |
| 活動中途複製半開的 db 當備份又繼續掃 | 備份不完整 |

## 10. 活動結束：主控合併

### 10.1 概念

```text
入口筆電  → 匯出站點包 ─┐
出口筆電  → 匯出站點包 ─┼→ USB → 管理員主控機 → 匯入全部 → 主控 CSV
側門筆電  → 匯出站點包 ─┘
```

### 10.2 每一台簽到站（結束時）

1. 確認已無排隊。  
2. **檔案 → 匯出站點包…**  
3. 存到 USB，例如：  
   `IFS_station_入口-1_20260809-180000.db`  
4. 可同時再匯出一份本機 CSV 作備份（可選）。  
5. 關閉程式前可再匯出一次站點包（以最後一次為準）。

### 10.3 管理員電腦

1. 建立資料夾，例如 `D:\IFS_Attendance\主控_20260809\`。  
2. 放入 `ifs_attendance.exe`，雙擊啟動（無需命令行）。  
3. **檔案 → 開啟 / 切換資料庫…**：  
   - 按「**建立新資料庫…**」，檔名輸入 `master.db`  
   - 角色選「**主控 Master**」→ 按「開啟」  
   - 畫面即切換為主控模式（頂列顯示「主控」）  

   日後直接雙擊啟動後，用同一對話框「選擇現有資料庫…」開回 `master.db` 即可。  
   （熟悉命令行者仍可用 `ifs_attendance.exe --master --db master.db` 直接啟動。）

4. **檔案 → 匯入站點包…**  
   - 一次可選多個 `.db`  
   - **可重複匯入**：相同造訪不會重複計算（依 visit_uid）  
5. 看畫面上：  
   - 總出席（去重）  
   - 需覆核  
   - 仍在場  
   - 主控儀表板預覽  
6. 需要主控 CSV 的 **CPD 欄**時：**檢視 → 活動 / 站點設定**，在**主控資料庫**填入與各站相同的 CPD 時間窗（例如入場 `14:30`–`15:00`、離場 `17:10`–`17:30`）。  
7. **檔案 → 匯出主控 CSV…**  
   - 此檔為**全場正式結果**  

### 10.4 主控如何配對跨站？

以「類別 + 編號」為同一人：

1. 收集所有站的入場、離場與跨站離場紀錄。  
2. 最早入場時間 → `first_check_in_at`。  
3. 將離場（含他站軟離場）配對到「尚未配對、且入場時間 ≤ 離場時間」的入場。  
4. 配對完成 → 狀態多為 **已離場**。  
5. 配對不上、時序怪異、多處仍開啟 → **需覆核**。

**例子**

| 情況 | 主控結果（簡述） |
|------|------------------|
| A 10:00 入場，B 12:00 跨站離場 | 已離場；進 10:00、出 12:00 |
| 只在 A 入場、從未離場 | 仍在場／僅入場；仍算有出席 |
| 只在 B 離場、從沒入場 | 僅離場（無入場）；需覆核 |
| 離場時間早於入場（時鐘不準） | 無法正常配對；需覆核 |

### 10.5 主控 CSV 欄位（摘要）

| 欄位 | 意義 |
|------|------|
| event | 活動名稱 |
| 保險中介人類別 / 編號 | 身分 |
| first_check_in_at | 全站最早入場 |
| last_check_out_at | 配對後的離場（若仍在場可能空白） |
| stations_seen | 出現過的站點 |
| visit_count | 造訪列數 |
| open_stations | 仍開啟的站 |
| status | 已離場／仍在場／僅入場／僅離場(無入場) 等 |
| needs_review | `1`＝建議人工檢查 |

---

## 11. 主控畫面與需覆核

匯入後請優先看：

1. **需覆核** 是否 > 0 → 打開主控 CSV 篩選 `needs_review=1`。  
2. **仍在場** 是否合理（活動已結束卻很多人在場 → 可能出口漏掃）。  
3. 抽查幾筆「A 進 B 出」是否 first_in / last_out 正確。

儀表板預覽僅顯示前幾筆；完整名單以主控 CSV 為準。

## 12. 指令列參數（進階，一般用戶可略過）

日常操作**不需要**指令列：換資料庫、切主控都在 **檔案 → 開啟 / 切換資料庫…** 完成。以下參數僅供批次／除錯用途：

```text
ifs_attendance.exe [選項]

  --db <路徑>        指定資料庫（預設：exe 旁 agent.db）
  --master           主控角色（允許多站開啟造訪並存；適合合併）
  --smoke            無視窗；印出版本／站點／人數後結束
  --soft-checkout    跨站離場（預設 true）
```

**範例**

```text
ifs_attendance.exe
ifs_attendance.exe --db D:\event\day1.db
ifs_attendance.exe --master --db master.db
ifs_attendance.exe --smoke --db agent.db
```

## 13. 操作守則

1. **同類別＋編號**才是同一人；同編號不同類別視為不同人。  
2. 無效 QR **不會**寫入資料庫。  
3. 離場後再入場 = **新的一筆人次**。  
4. 程式開啟中請用「匯出站點包」，不要硬拷正在使用的 `agent.db`。  
5. 電腦時鐘／時區要正確（時間為本機牆上時間）。  
6. 重大操作前備份 `agent.db`。  
7. 主控正式名單以**合併後的主控 CSV**為準，不以單機「目前在場」為準。

## 14. 常見問題與排除

| 現象 | 可能原因與處理 |
|------|----------------|
| 中文變□□ | Windows 缺中文字型；一般 Win10/11 有微軟雅黑即可 |
| 掃了沒反應 | 程式會自動保持焦點；若仍無反應，確認掃描器有送 Enter（可用記事本測） |
| **中途關機／當機** | 直接重開程式即可：每一筆掃描都即時寫入資料庫，重開後人數、紀錄完全接續，不會遺失或重複 |
| 要改用另一個資料庫／切主控 | 檔案 → 開啟 / 切換資料庫…（免指令列、免重開程式） |
| 一直「重複入場」 | 本機仍在場；先按 **F2** 用離場掃，或確認是否掃錯人 |
| 出口顯示「跨站點離場」 | **正常**（入場在別台）；務必仍要掃 |
| 主控再匯入沒增加 | 正常（重複站點包會略過） |
| 各站「目前在場」對不上 | 正常；只看主控合併結果 |
| 全場已結束仍很多人「仍在場」 | 出口可能漏掃；查主控 CSV |
| 音效太吵 | 檢視 → 音效 → 關 |
| 要投放大螢幕 | F11 全螢幕 |

## 15. 列印用檢查清單

### 活動前（每台簽到筆電）

- [ ] 獨立資料夾 + `ifs_attendance.exe`  
- [ ] 站點名設好（入口-x／出口-x）  
- [ ] 活動名稱各站一致  
- [ ] 入場站預設 **入場**；離場站預設 **離場**  
- [ ] 實掃一張 QR 測試入場與離場  
- [ ] 時區正確；需要時 F11  

### 活動中

- [ ] 入場只掃入場；離場只掃離場  
- [ ] 出口**每位離場者都掃**（含他站入場）  
- [ ] 不共用即時同步的資料庫檔  
- [ ] 注意結果卡是否成功／重複  

### 活動後

- [ ] 每台：**匯出站點包** → USB  
- [ ] 管理員：雙擊 exe → **檔案 → 開啟 / 切換資料庫…** → 建立／選擇 `master.db` → 角色「主控 Master」→ 開啟  
- [ ] 匯入所有站點包  
- [ ] 檢查需覆核、仍在場  
- [ ] **匯出主控 CSV** 並歸檔  
- [ ] 站點包 + master.db + CSV 一併備份（權限控管）

## 16. 個資與歸檔

資料庫含中介人類別、編號與時間戳記，屬活動敏感資料：

- USB 與主控檔勿任意外傳  
- 歸檔於受控目錄，並依貴機構保存期限處理  
- 不需要時安全刪除測試資料

## 附錄：單機 vs 全場

| 問題 | 看哪裡 |
|------|--------|
| 這一台現在有多少人在場？ | 簽到站「目前在場」 |
| 這一台今天有多少不同的人來過？ | 「累計人次」（不重複）；本機 CSV 另列每次入場／離場明細 |
| 整場有哪些人來過？ | **主控 CSV**（去重出席） |
| 誰從 A 進、從 B 出？ | 主控 CSV 時間與 stations_seen |
| 誰可能漏掃或異常？ | 主控 `needs_review=1` |
